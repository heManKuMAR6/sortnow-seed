# Contributing

Use a feature branch and a PR to main. Read SEED_PROJECT_GUIDE.md first and update it when behavior or decisions change. Install dependencies only when needed. Run targeted tests for behavior/security changes and build checks for type/integration changes. Reserve full checks for CI or cross-cutting changes; audit when dependencies change. Include behavior changes, validation evidence, and compatibility limitations in the PR. Tests must cover new trust boundaries and schedule behavior. Never commit credentials, real customer data, node_modules, or build artifacts. Keep the core framework-independent. UI adapters must preserve host content and escape untrusted text.
